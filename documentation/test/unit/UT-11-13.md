
**Description:**
Validates that submitting a valid password change through `MustChangePasswordView.form_valid()` clears the `AccountProfile.must_change_password` flag and redirects to the password-change done page. Validation includes when the `User` is `None` and a redirect occurs with a warning message.

**Preconditions:**

- Authenticated test user created via `get_user_model().objects.create_user(...)`.
- `AccountProfile` exists for the user with `must_change_password = True`.
- Django session middleware is active on the request in test context.
- Routes for `/accounts/password_change/` and `/accounts/password_change/done/` are configured.

**Test Data:**

- Generated username and email (environment overrides possible).
- Old password set during user creation (environment override `TEST_PASSWORD` possible).
- New password distinct from old (environment override `TEST_NEW_PASSWORD` possible).

**Execution Steps:**

Normal password change route:

1. Create a POST request to `/accounts/password_change/` and attach `request.user` to the created user.
2. Process the request through `SessionMiddleware` and save the session.
3. Build a valid `PasswordChangeForm` with fields `old_password`, `new_password1`, `new_password2`.
4. Assert `form.is_valid()` returns **True** (log errors if not).
5. Instantiate `MustChangePasswordView`, set `view.request` and `view.object = user`.
6. Call `view.form_valid(form)` and capture `response`.
7. Refresh `AccountProfile` from database and verify `must_change_password` is now **False**.
8. Assert `response.status_code == 302` and `"/accounts/password_change/done/" in response.url`.

User is None:

1. Construct a GET request to simulate an anonymous or unauthenticated request.
2. The request passes through the using the dummy function.
3. The middleware will return the original request unadulterated.

**Expected Result:**

- Password change form is valid.
- `AccountProfile.must_change_password` flips from **True** to **False**.
- The response is an HTTP **302** redirect to the password-change done page.
- When no user is attached to a request, the original request is returned.

**Post-Conditions:**

- User credentials updated to the new password.
- Session remains valid; no exceptions thrown by the view.

FR-11
