**Description:**
This suite validates the JSON response behavior of all analyzer-specific status endpoints (`bandit_status_json`, `dodgy_status_json`, `mypy_status_json`, `semgrep_status_json`→ and `vulture_status_json`). Each endpoint should correctly report the analysis status and findings count for a given `SubmittedFile` record that has a completed `Run` instance.

**Preconditions:**

- Authenticated test user with valid session (if required).
- Active test media configuration (`TEMP_MEDIA` or equivalent).
- A valid `SubmittedFile` object with a unique SHA-256 hash (`self.vuln_file → sample_files/bandit_ringer_test.py`). Good for testing `Run` creation and json return (not testing actual analyzer).
- Corresponding URL routes for each analyzer status view defined in Django `urls.py`.
- Each test run uses a `Run` object representing a completed analysis with consistent status and findings count.

**Test Data:**

| Field          | Example Value                                   | Notes                                          |
| -------------- | ----------------------------------------------- | ---------------------------------------------- |
| File Name      | `sample_files/bandit_ringer_test.py`            | Uploaded file used in test setup               |
| Analyzer       | `bandit`, `dodgy`, `mypy`, `semgrep`, `vulture` | One per test case                              |
| Run Status     | `Run.Status.COMPLETED`                          | Represents a completed analyzer run            |
| Findings Count | `3`                                             | Used to validate correct JSON field population |
| Start Time     | `timezone.now()`                                | Timestamp of analyzer execution                |

**Execution Steps:**

### 1️. Analyzer JSON View (Generic Pattern)

1. Create a `Run` object for a specific analyzer, e.g. `"bandit"`, with status `COMPLETED` and findings_count `3`.
2. Perform a GET request to the corresponding JSON endpoint, e.g. `reverse("bandit_status_json")`.
3. Parse the response JSON and validate key-value pairs.

**Expected Result:**

- Response returns **HTTP 200**.
- The file's `sha256` key is present in the returned JSON.
- The nested JSON for that key includes:
  - `"status": "COMPLETED"`
  - `"findings_count": 3`

---

### 2. Applied Across All Analyzers

Each analyzer’s test case (`bandit`, `dodgy`, `mypy`, `semgrep`→ and `vulture`) follows the same pattern to ensure consistency across all JSON endpoints. The test suite ensures identical behavior and schema across each analyzer, confirming uniform front-end polling compatibility.

**Post-Conditions:**

- Each endpoint correctly serializes the database state for completed `Run` entries.
- Returned JSON matches the expected schema for UI consumption.
- No extraneous or missing keys appear in the response.
- Test database remains consistent after execution, with temporary test data isolated.
