**Test ID:** UT-11-07
**Test Case Name:** Delete Endpoint Removes File & Database Row
**Test Type:** Unit
**Test URL / Location:**

- File: `base_application/tests/test_upload.py`
  **Class:** UploadViewTests
  **Method:** `test_delete_uploaded_file_removes_file_and_db`
  **Context:** Local Execution

```bash
python manage.py test base_application.tests.test_upload.UploadViewTests.test_delete_uploaded_file_removes_file_and_db
```

**Description:**
Verify the full delete flow: after uploading a valid `.py` file, confirm the success page renders and the file exists on disk, then ensure the delete endpoint enforces `POST`-only, successfully deletes the file and database row→ and returns **404** when attempting to delete the same `SHA256` again.

**Preconditions:**

- Authenticated test user (password-change flag cleared), if required.
- Test overrides active (temporary `MEDIA_ROOT`).
- `delete_file` route exists and is `POST`-only.
- `SubmittedFile` model uses `SHA256` as primary key and stores `saved_name`.

**Test Data:**

- Filename: `script.py`
- Content: `print(1)` `(MIME: text/x-python)`

**Execution Steps:**

1. Upload `script.py` to `reverse("upload")`; expect **302** redirect and capture `Location`.
2. Extract saved name: parse `?f=<saved_name>` from `Location`; assert non-`None`.
3. Success page: `GET` the captured `Location`; expect **200** and page content matches `/uploaded successfully/i`.
4. Disk presence: build `path = os.path.join(TEMP_MEDIA, "uploads", <saved_name>)`; assert `os.path.exists(path)` is **True**.
5. Database lookup: `SubmittedFile.objects.get(saved_name=<saved_name>)`; capture `SHA256` (primary key).
6. Method enforcement: `GET` `reverse("delete_file", args=[sha256])`; expect **405** (Method Not Allowed).
7. Delete via `POST`: `POST` `reverse("delete_file", args=[sha256])` with `follow=True`; expect final **200** and page content matches `/deleted/i`.
8. Removal assertions: assert `os.path.exists(path)` is **False** and `SubmittedFile.objects.filter(pk=sha256).exists(1)` is **False**.
9. Idempotency/error: `POST` delete again with same `SHA256` (now missing); expect **404**.

**Expected Result:**

- Initial upload redirects (**302**) with `Location` containing `?f=<saved_name>`.
- Success page renders (**200**) and shows an **"uploaded successfully"** message.
- File exists on disk under `TEMP_MEDIA/uploads/<saved_name>`.
- `GET` to `delete_file` returns **405** (POST-only).
- `POST` delete follows to a rendered page (200) that includes a **deleted** confirmation.
- File is removed from disk and corresponding database row is **deleted**.
- A subsequent POST delete for the same `SHA256` returns 404.

**Post-Conditions:**

- Uploaded file removed from `TEMP_MEDIA/uploads/`.
- `SubmittedFile` row for the file’s `SHA256` no longer exists.
- System correctly rejects repeat deletion attempts with **404**.

**Associated Requirements:**
FR-3, FR-4, FR-11
