**Description:**

This test suite will serve to validate behavior of the complete pipeline of communication (both invalid and valid) of
the chat bot. Then finally the test of the presence of a GPU in the inference output test.

**Preconditions:**

- Django test client is made available.
- `SECURE_SSL_REDIRECT=False` override setting is made to prevent 301 errors.
- Chat endpoint routes (`chat_reset`, `chat_llm`) are configured properly.
- Local GGUF model accessible at `models/<GGUF_FILE_NAME>`.
- Proper NVIDIA Driver and CUDA Runtime is installed.
- Patching and mocking is enabled for GPU inference, ChatSession save and general failures.

**Test Data:**

| Field                          | Example Value                                  | Notes                            |
| ------------------------------ | ---------------------------------------------- | -------------------------------- |
| Missing Prompt                 | `""`                                           | Validates 400 return             |
| GPU Check Command              | Bash invocation of llama_cpp                   | Detects GPU device               |
| Invalid JSON Payload Injection | Sends raw string `"not-a-json"` to JSON parser | Triggers JSON decoding exception |

**Patches for Failure Simulations:**

| Patches                                             | What Was Patched / Mocked                       | Purpose of Failure Injection                  |
| --------------------------------------------------- | ----------------------------------------------- | --------------------------------------------- |
| `patch("base_application.models.ChatSession.save")` | Overrides model `.save()` to raise an exception | ChatSession database write failure simulation |

**Automated Execution Steps:**

#### Endpoint Path and Redirect Behavior

1. Validate URL resolution for `/api/chat_reset/` and `/api/chat_llm/`. (`test_urls`)
2. Confirm missing trailing slash triggers redirect (**301**). (`test_check_redirect`)

#### Chat Reset Workflow

1. POST → returns `{ "status": "reset" }`. (`test_chat_reset_post`)
2. GET → returns **405**. (`test_chat_reset_not_post`)

#### Chat LLM Input Validation

1. Missing prompt returns **400** + error string. (`test_chat_llm_missing_prompt`)
2. Wrong method returns **405**. (`test_chat_llm_wrong_method`)

#### Database Save Failure Handling (`test_chat_llm_chat_session_save_failure`)

1. Patch `ChatSession.save` to raise exception.
2. Confirm **500** return with diagnostic keys.

#### Bad Payload Handling (`test_chat_llm_bad_payload_exception`)

1. Provide invalid JSON.
2. Confirm **500** with descriptive error string.

#### GPU Detection (`test_chat_inference_gpu_found`)

1. Run subprocess to load local GGUF model (via NVIDIA and CUDA).
2. Assert `"Device"` found and `"CPU"` not found.

**Expected Result:**

- All endpoints respond with their correct HTTP status codes.
- Exception conditions are percolated back in a well organized structure for verification.
- ChatSession model entry failure is cleanly presented.
- llama-cpp-python utilizes the GPU for hardware acceleration.

**Post-Conditions:**

- API behavior remains stable across both invalid and valid inputs.
- All responses are structured well (JSON) and predictable.
