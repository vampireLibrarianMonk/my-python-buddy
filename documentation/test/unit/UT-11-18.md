**Test Case Name:** Run Detail View – Rendering File Content and Findings
**Test Type:** Unit

- **File:** `base_application/tests/test_analyze_file_view.py`

  - `test_run_detail_renders_with_findings`

```bash
python manage.py test base_application.tests.test_analyze_file_view.AnalyzeFileViewTests.test_run_detail_renders_with_findings
```

**Description:**
This test verifies that the **Run Detail** view (`run_detail`) properly renders when a completed analyzer run exists. It ensures the view returns valid HTML with file metadata and the associated findings context for display.

The test focuses on confirming that the rendered page includes both the file content and the analyzer findings, validating end-to-end context injection into the template.

**Preconditions:**

- Authenticated test user with valid session (if required).
- Active test media configuration (`TEMP_MEDIA` or equivalent).
- Valid `SubmittedFile` instance (`self.vuln_file → sample_files/bandit_ringer_test.py`).
- A completed `Run` record linked to this file (`Run.Status.COMPLETED`).
- Django route `run_detail` defined with a primary key argument resolvable via `reverse()`.

**Test Data:**

| Field      | Example Value                        | Notes                            |
| ---------- | ------------------------------------ | -------------------------------- |
| File Name  | `sample_files/bandit_ringer_test.py` | Sample vulnerable test file      |
| Analyzer   | `"bandit"`                           | Analyzer producing results       |
| Run Status | `Run.Status.COMPLETED`               | Confirms completed analysis      |
| Start Time | `timezone.now()`                     | Timestamp of run initiation      |
| Route Args | `[run.pk]`                           | Used to retrieve run detail view |

**Execution Steps:**

### 1️. Run Detail Rendering

1. Create a completed `Run` record for the vulnerable file.
2. Perform a GET request to `reverse("run_detail", args=[run.pk])`.
3. Verify successful page load and correct context variables.

**Expected Result:**

- Response returns **HTTP 200**.
- HTML response contains the saved file name.
- Template context includes `"file_content"` and `"findings"` keys.

**Post-Conditions:**

- The `Run` object remains persistent and unchanged after execution.
- Page renders without exceptions or missing context data.
- Findings and file contents are correctly exposed to the frontend for user inspection.
- No database side effects occur from the GET request.
