**Description:**
This suite validates the behavior of the `run_analyzer` endpoint under two core conditions:

1. When no existing `Run` record is found for a given `(SubmittedFile, analyzer)` pair.
2. When a valid `Run` record exists and must transition from **PENDING** to **REQUESTED** while returning a success response.

The tests confirm that the endpoint enforces pre-run validation, updates state correctly→ and returns appropriate JSON responses for front-end orchestration.

**Preconditions:**

- Authenticated test user with valid session (if required).
- Active test media configuration (`TEMP_MEDIA` or equivalent).
- At least one persisted `SubmittedFile` object with a valid SHA-256 hash (`self.clean_file → sample_files/sample.py`).
- Analyzer slug `"bandit"` resolvable through URL route `run_analyzer`.
- Route name `run_analyzer` correctly defined and accessible via Django `reverse()`.

**Test Data:**

| Field               | Example Value             | Notes                                                          |
| ------------------- | ------------------------- | -------------------------------------------------------------- |
| File Name           | `sample_files/sample.py`  | File already uploaded and linked to a `SubmittedFile` instance |
| Analyzer            | `"bandit"`                | One of the registered analyzer keys                            |
| Initial Run State   | `Run.Status.PENDING`      | Used in the valid transition case                              |
| Expected Transition | `Run.Status.REQUESTED`    | Expected after valid POST                                      |
| Error Condition     | No preexisting Run object | Should yield 400 with error message                            |

**Execution Steps:**

### 1️. `test_run_analyzer_requires_existing_run`

1. POST to `reverse("run_analyzer", args=[self.clean_file.sha256, "bandit"])` with **no** existing `Run`.
2. Capture response JSON and status code.

**Expected Result:**

- Response returns **HTTP 400**.
- JSON includes `"Error: Run not initialized"` within the `status` field.

---

### 2. `test_run_analyzer_marks_requested_and_returns_json`

1. Create a `Run` record:
   ```python
   run = Run.objects.create(submitted_file=self.clean_file, analyzer="bandit", status=Run.Status.PENDING)
   ```
2. POST to the same endpoint.
3. Refresh the `Run` instance from the database.

**Expected Result:**

- Response returns **HTTP 200**.
- `run.status` updates to **Run.Status.REQUESTED**.
- JSON response includes `"status": "Queued"`.

**Post-Conditions:**

- The `Run` record for the test file reflects its final `REQUESTED` state in the database.
- The error handling path prevents duplicate or premature analyzer runs.
- The endpoint consistently returns machine-readable JSON, suitable for asynchronous orchestration from the user interface.
- No orphaned or duplicate `Run` records are created during tests.

FR-6, FR-11
