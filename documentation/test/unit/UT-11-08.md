**Test Case Name:** Duplicate Content Results in Single Database Row
**Test Type:** Unit  
**Test URL / Location:**  
    - File: `base_application/tests/test_upload.py`  
    - GitHub Commit URL: 
**Class:** UploadViewTests  
**Method:** 
- Helper: `_fname_from_redirect(resp)`
- Test: `test_duplicate_content_creates_single_row`
**Context:** Local Execution
```bash
python manage.py test base_application.tests.test_upload.UploadViewTests.test_duplicate_content_creates_single_row -v 2
``` 

**Description:**  
Uploading two different filenames with identical file content should result in the same saved artifact `(same ?f=<saved_name> in the redirect)` and exactly one database row, since the primary key is the file’s `SHA-256`.

**Preconditions:**  
- Authenticated test user (password-change flag cleared), if required.
- Test overrides active (temporary `MEDIA_ROOT`).
- `SubmittedFile` model uses `SHA-256` as primary key (content-addressed storage).

**Execution Steps:**  
1. `POST` `a.py` to `reverse("upload")`; expect `HTTP` **302**.
2. Extract `file_name_one` via `_fname_from_redirect(response_one)` `(parses ?f=<saved_name>)`.
3. `POST` `b.py` `(same bytes)` to `reverse("upload")`; expect `HTTP` **302**.
4. Extract `file_name_two` via `_fname_from_redirect(response_two)`.
5. Assert `file_name_one == file_name_two`.
6. Assert `SubmittedFile.objects.count() == 1`.

**Expected Result:**  
- Both uploads return `HTTP` **302** with a redirect containing `?f=<saved_name>`.
- The `f` values from both redirects are identical.
- Exactly one `SubmittedFile` row exists (deduplicated on `SHA-256`).

**Post-Conditions:**  
- Single persisted artifact referenced by both uploads.
- Database remains at one row for the shared content.
