**Test Case Name:** Analyzer Version Detection – Validation of Known and Unknown Tool Handling
**Test Type:** Unit

- **File:** `base_application/tests/test_analyzers.py`

  **Methods:**
  - `test_get_analyzer_version_known_and_unknown`

```bash
python manage.py test base_application.tests.test_analyzers.AnalyzerTests.test_get_analyzer_version_known_and_unknown
```

**Description:**
This test validates the behavior of the `get_analyzer_version()` utility across both recognized and unrecognized analyzers.
It confirms that valid analyzers (`bandit`, `dodgy`, `mypy`, `semgrep`, `vulture`) correctly return non-empty version strings, while an unsupported tool safely returns `"unknown"`.

The test ensures predictable version reporting for traceability, reproducibility and metadata logging of analyzer runs.

**Preconditions:**

- Authenticated test user with valid session (if required).
- Active test media configuration (`TEMP_MEDIA` or equivalent).
- All supported analyzers (`bandit`, `dodgy`, `mypy`, `semgrep`, `vulture`) installed and accessible in the environment.
- The `get_analyzer_version()` function implemented in the analyzer utility module.
- The test environment configured with proper Python PATH visibility for analyzer binaries.
- Unknown analyzer name (`faux_tool_does_not_exist`) used as a negative control to test safe fallback behavior.

**Test Data:**

| Field            | Example Value                                                               | Notes                                   |
| ---------------- | --------------------------------------------------------------------------- | --------------------------------------- |
| Analyzer Names   | `bandit`, `dodgy`, `mypy`, `semgrep`, `vulture`, `faux_tool_does_not_exist` | Covers both valid and invalid analyzers |
| Expected Type    | `str`                                                                       | Version must be returned as a string    |
| Expected Output  | Non-`"unknown"` for valid analyzers                                         | `"unknown"` for unsupported analyzer    |
| Version Source   | CLI version flag (e.g., `--version`)                                        | Extracted via subprocess call           |
| Negative Control | `"faux_tool_does_not_exist"`                                                | Ensures error-safe handling             |

**Execution Steps:**

### 1️. Analyzer Version Retrieval

1. Call `get_analyzer_version(<tool_name>)` sequentially for each supported analyzer.
2. Assert that the return value is a string.
3. Verify that known analyzers return valid, non-empty versions distinct from `"unknown"`.
4. Call the function for an invalid analyzer name to validate fallback safety.

**Expected Result:**

- For all valid analyzers (`bandit`, `dodgy`, `mypy`, `semgrep`, `vulture`):
  - Return type is `str`.
  - Returned version is **not equal to** `"unknown"`.
- For the invalid analyzer (`faux_tool_does_not_exist`):
  - Return type is `str`.
  - Returned version is exactly `"unknown"`.

**Post-Conditions:**

- Version reporting behaves consistently across analyzers.
- No exceptions are raised for missing or unsupported analyzers.
- Function remains safe, deterministic, and resilient to environment variance.
- Output suitable for inclusion in audit metadata and logs.

FR-7, FR-11
