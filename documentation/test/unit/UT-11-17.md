**Description:**
This suite verifies that each analyzer-specific JSON status endpoint (`bandit_status_json`, `dodgy_status_json`, `mypy_status_json`, `semgrep_status_json`, `vulture_status_json`) correctly reports a **NOT_REQUESTED** state when no `Run` record exists for a given file.
The tests confirm that the backend consistently provides default status values for uninitialized analyzers, supporting reliable frontend polling and dashboard synchronization.

**Preconditions:**

- Authenticated test user with valid session (if required).
- Active test media configuration (`TEMP_MEDIA` or equivalent).
- No `Run` objects created for any analyzers before each test executes.
- Django URL routes for all analyzer status JSON views correctly configured and resolvable via `reverse()`.

**Test Data:**

| Field           | Example Value                                   | Notes                                     |
| --------------- | ----------------------------------------------- | ----------------------------------------- |
| Analyzer        | `bandit`, `dodgy`, `mypy`, `semgrep`, `vulture` | Tested individually                       |
| Expected Status | `"NOT_REQUESTED"`                               | Returned when no corresponding run exists |
| Database State  | No existing `Run` rows                          | Ensures endpoint default behavior         |

**Execution Steps:**

### 1️. Analyzer JSON View (Generic Pattern)

1. Confirm no `Run` objects exist for the test file.
2. Send a GET request to each analyzer’s JSON endpoint (e.g., `reverse("bandit_status_json")`).
3. Parse response JSON and verify that the correct file SHA-256 appears as a key.

**Expected Result:**

- Response returns **HTTP 200**.
- JSON structure includes `{ "<sha256>": {"status": "NOT_REQUESTED"} }`.
- No `findings_count` field appears since no runs exist.

---

### 2. Applied Across All Analyzers

The five test methods (`bandit`, `dodgy`, `mypy`, `semgrep`, `vulture`) reuse identical logic to validate endpoint parity. This ensures that each analyzer view behaves uniformly when reporting unrequested runs.

**Post-Conditions:**

- No `Run` records are inserted or modified.
- Each endpoint consistently returns `"NOT_REQUESTED"` for analyzers with no prior runs.
- Response schema remains minimal and uniform across analyzers.
- Database and media isolation preserved post-execution.
