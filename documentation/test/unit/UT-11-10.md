**Test ID:** UT-11-10
**Test Case Name:** Code Security Checks, Code Quality and Formatting Checks
**Test Type:** Unit
**Test URL / Location:**

- File: `.pre-commit-config.yaml`
- File: `pyproject.toml`

**Command Line:**

All modules for all files

```bash
pre-commit run --all-files
```

One Module at a time:

```bash
pre-commit run bandit --all-files
pre-commit run black --all-files
pre-commit run codespell --all-files
pre-commit run detect-secrets --all-files
pre-commit run flake8 --all-files
pre-commit run isort --all-files
pre-commit run prettier --all-files
```

**Associated Tools:**

- pre-commit: Enforcement mechanism of code quality.
- bandit: Finder for common vulnerabilities and insecure coding patterns.
- black: Enforces consistent style.
- codespell: Detects common spelling errors.
- detect-secrets: Finder for hardcoded credentials like API keys or passwords to prevent leaks.
- flake8: Code error finder and Python linter style guide violations.
- isort: PEP 8 organization of imports
- prettier: Enforces consistent style in files.

**Description:**

After configuring and possibly updating repos `pre-commit autoupdate --rep {REPO_URL}` these configurations and checks ensure that a standard is upheld prior to commiting code to a repository.

**Preconditions:**

- `.pre-commit-config.yaml` and `pyproject.toml` exist in the project root.
- Required hooks and dependencies are installed using `pre-commit install`.
- Conda environment is active with compatible Python version (**3.10+**).

**Execution Steps:**

| Step | Action                                                             | Expected Response                                                  |
| ---- | ------------------------------------------------------------------ | ------------------------------------------------------------------ |
| 1    | Run `pre-commit run --all-files` in project root                   | All enabled hooks execute without error                            |
| 2    | black formats Python files                                         | Code is reformatted to match Black style (`line-length = 160`)     |
|      | _pyproject.toml_                                                   |                                                                    |
| 3    | isort orders imports based on Black profile                        | Imports match groupings with trailing commas and line-length limit |
|      | _pyproject.toml_                                                   |                                                                    |
| 4    | codespell runs on non-ignored files                                | Common spelling mistakes are flagged and corrected                 |
| 5    | prettier formats JSON, YAML→ and Markdown files (excluding config) | Affected files are rewritten with Prettier style                   |
| 6    | flake8 flags Python lint violations using `pyproject.toml` config  | Violations are listed, respecting ignore rules and line length     |
|      | _pyproject.toml_                                                   |                                                                    |
| 7    | bandit scans for security issues, excluding `tests/`               | Outputs list of any security-related findings                      |
| 8    | detect-secrets scans for secrets or credentials in source          | Secrets (if any) are flagged and require remediation               |

**Expected Result:**

- All tools successfully complete without blocking commits.
- Codebase remains compliant with security, formatting→ and linting standards.
- Hooks automatically prevent issues from reaching version control.

**Post-Conditions:**

- All staged and committed code conforms to the project's style, lint and security policies.
- The Git working directory remains clean (git status shows no modified files unless hook-modified).
- Any auto-correctable issues are fixed in-place by their respective hooks (e.g., black, isort, prettier).
- No secrets, insecure patterns, or merge conflicts persist in the committed source.
- Developers receive immediate feedback, reducing review churn and CI pipeline failures.
