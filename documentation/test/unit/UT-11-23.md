**Description:**
This suite verifies the **error-handling logic** for each analyzer’s execution path when internal runtime exceptions occur.
Each test forces a controlled failure (via `patch`) inside the analyzer’s core function or subprocess call to ensure the run correctly transitions to the **ERRORED** state and returns a structured error dictionary.

These tests provide exception handling given that when the analyzers fail they fail gracefully without halting the pipeline, preserving data integrity and returning useful diagnostic information.

**Preconditions:**

- All analyzers implemented and accessible within `base_application.analyzers`.
- Exception injection applied through `unittest.mock.patch` targeting specific failure points:
  - Bandit → `BanditManager.run_tests`
  - Dodgy → `check_file_contents`
  - MyPy → `mypy_api.run`
  - Semgrep → `subprocess.run` of a usual cli arguments and flags.
  - Vulture → `Vulture.scan`
- Each `Run` object begins in `Run.Status.REQUESTED` state.
- A valid clean file object (`self.clean_file`) provided for testing.

**Test Data:**

| Field                | Example Value                                   | Notes                                                    |
| -------------------- | ----------------------------------------------- | -------------------------------------------------------- |
| Analyzer Names       | `bandit`, `dodgy`, `mypy`, `semgrep`, `vulture` | Each analyzer tested individually                        |
| Exception Type       | `RuntimeError("failed task")`                   | Simulated runtime failure                                |
| Initial Status       | `Run.Status.REQUESTED`                          | Pre-execution state                                      |
| Expected Status      | `Run.Status.ERRORED`                            | Verifies correct error state transition                  |
| Expected Output Keys | `"error"`                                       | Returned dictionary includes descriptive error message   |
| Assertion Target     | `"failed task"`                                 | Confirms correct propagation of the raised error message |

**Execution Steps:**

### 1️. Exception Injection and Error Handling

1. Patch the relevant analyzer component to raise `RuntimeError("failed task")`.
2. Create a `Run` instance with analyzer type set and status `REQUESTED`.
3. Execute the corresponding analyzer (e.g., `run_bandit_analyzer(run)`).
4. Refresh the `Run` object from the database.
5. Validate both the status and returned error dictionary.

**Expected Result:**

- `Run.status` changes to **ERRORED**.
- `Run.completed_at` is populated.
- Result includes `"error"` key.
- The error message `"failed task"` appears within the result.
- No uncaught exceptions propagate to the test runner.

**Post-Conditions:**

- Each analyzer gracefully handles internal exceptions without breaking system flow.
- The database accurately reflects the errored state and completion timestamp.
- Error messages are standardized and available for logging and diagnostics.
- No side effects remain in the task queue or pending runs.
