**Description:**
This suite validates the behavior of the `analyze_file_view` endpoint for both GET and POST requests. It ensures that the view correctly prefills metadata in the GET response, handles validation errors for invalid POST requests and successfully creates `Run` records when valid analyzer input is provided.

**Preconditions:**

- Authenticated test user (password-change flag cleared), if required.
- Test overrides active (temporary `MEDIA_ROOT` assigned to `TEMP_MEDIA`).
- At least one valid `SubmittedFile` instance with a known `sha256` hash (`self.clean_file` → `sample_files/sample.py`).
- Analyzer choices available in `AnalyzerSelectForm.ANALYZER_CHOICES`.
- URL route name `analyze_file` defined and resolvable via Django `reverse()`.

**Test Data:**

| Field            | Example Value                                                             | Notes                                                            |
| ---------------- | ------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| File Name        | `sample_files/sample.py`                                                  | Valid file uploaded and persisted                                |
| Analyzer Choices | All available analyzers (`bandit`, `dodgy`, `mypy`, `semgrep`, `vulture`) | Retrieved dynamically from `AnalyzerSelectForm.ANALYZER_CHOICES` |
| Invalid Data     | `{}`                                                                      | Represents submission with no analyzers selected                 |

**Execution Steps:**

### 1️. test_analyze_file_view_get_prefills_form`

1. Perform a GET request to `reverse("analyze_file", args=[self.clean_file.sha256])`.
2. Inspect the response status and HTML content.

**Expected Result:**

- Response returns HTTP 200.
- Page contains the saved filename and the `<form>` element.

---

### 2. `test_analyze_file_view_post_invalid`

1. Perform a POST request with an empty data payload `{}`.
2. Validate redirect behavior and message content.

**Expected Result:**

- Response redirects back to the same `analyze_file` URL.
- Flash message includes `"Please choose at least one analyzer"`.

---

### 3. `test_analyze_file_view_post_creates_runs`

1. Select the first available analyzer from `AnalyzerSelectForm.ANALYZER_CHOICES`.
2. POST data including `file_name`, `analyzers`→ and `llm_notes`.
3. Retrieve `Run` records filtered by `submitted_file`.

**Expected Result:**

- Response returns HTTP 200.
- A `Run` object is created with the analyzer matching the submitted choice.
- All runs for this file are marked `REQUESTED` in `Run.Status`.

**Post-Conditions:**

- The created `Run` entries persist in the database after test execution.
- The `SubmittedFile` remains associated with its original `sha256`.
- The view remains stable across GET and POST interactions without raising exceptions.
