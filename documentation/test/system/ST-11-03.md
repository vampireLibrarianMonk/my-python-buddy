**Description:**

This test suite will serve to verify both asynchronous (ASGI) and synchronous (WSGI) gateway interface aspects of the
web application’s networking layer.

- `TestCoreWebSocket`:
  - Verify that one can establish a WebSocket connection.
  - The connection can end and receive a group-broadcast message.
  - Properly returns the expected JSON payload.
- `TestAnalyzerConsumer`:
  - Clean connect (joins expected group) and disconnect behavior (no resulting errors).
  - Message send to group triggers the end to end serialized update over the socket.
  - Confirms arbitrary text sent by the client is safely ignored.
- `TestWSGI`:
  - Environment settings check
  - Check instance via import and the factory called
  - Single valid round-trip request

**Preconditions:**

- Django test client is made available.

**Test Data:**

| Field       | Example Value                                                            | Notes                       |
| ----------- | ------------------------------------------------------------------------ | --------------------------- |
| Data String | `"data"`                                                                 | Group send on channel layer |
| Update JSON | `{"type": "send_update", "data": {"status": "running", "progress": 55}}` | Group send on channel layer |

**Automated Execution Steps:**

### Endpoint Path and Redirect Behavior

1. Behavior check for connect/disconnect to `/ws/analyzer/test_connection/`. (`async_test_connect_and_disconnect`)
2. Send update to group layer and await response. (`async_test_send_update`)

### Chat Reset Workflow

1. POST → returns `{ "status": "reset" }`. (`test_chat_reset_post`)
2. GET → returns **405**. (`test_chat_reset_not_post`)

**Expected Result:**

- Clean connect and disconnect of the WebSocket session.
- Clean group join and removal with no post connection message delivery.
- Clean round trip for asynchronous (ASGI) update, returning the expected JSON payload.
- Clean handling of messaging to the client when the consumer performs am operation where we expect no response (no-op).
- Clean round trip for synchronous (WSGI) test, confirming that the handler will load and then post a _200_ response.

**Post-Conditions:**

- WebSocket connection is closed and no longer receives group messages after the disconnect occurs.
- Group analyzer channel no longer has any active membership for now disconnected consumer.
- Any attempt at a broadcast is sent only once and is correctly serialized into JSON.
- WSGI application stays running and can respond to basic requests without any issues.
