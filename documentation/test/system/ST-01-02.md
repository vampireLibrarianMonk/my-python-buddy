# System Test 01-02 User Access to Web Application 

**Test Type:** System  
**Context:** Connectivity and Availability of Web Application upon Deployment 
**Context Ladder** Local then Cloud Deployment
**Test ID:** ST-01-02

**Description:**  
This `system` test will validate the accessibility of the application once it is 1) deployed locally then 2) deployed to the cloud. 

The Django framework is served by uvicorn which enables https with static file support via Whitenoise. Data is persisted by SQLite.

**Test URL:**  
https://github.com/vampireLibrarianMonk/my-python-buddy/commit/dc83d2808ab6a583275c92ced5cd7253a9d3e84a

**Preconditions:**  
- Computer instance (with cloud a public IP is provided) is provisioned with running code and is accessible to the User.
- User has been notified that they have to accept self-signed certificate for HTTPS access.
- Environment file configured with valid database URL and secrets.
- User has been given starter credentials.

### Test Execution Steps

* Note that actual values from health and table row data will differ (analyzer selection) will differ per User input.

| Step | Action                                                               | Expected Response |
|------|----------------------------------------------------------------------|-------------------|
| 1 | Administrator creates a new user via the cmd line                    | User account successfully created |
| 2 | User logs in and is redirected to change password                    | Password change page is shown immediately |
| 3 | User uploads `sample.py`                                             | Application accepts file and confirms upload |
| 4 | User selects `View/Download`                                         | Browser opens uploaded file in new tab |
| 5 | User selects `Analyze`, chooses analyzers and selects `Run analysis` | Analyzer page loads, analysis starts with selected analyzers |
| 6 | User arrives at `Analyze code` page                                  | Page renders with analysis controls |
| 7 | User selects `Upload` from top-right menu                            | User is redirected back to submission page with uploaded files table shown |
| 8 | User selects `View/Download` from uploaded row                       | File opens in a new browser tab |
| 9 | User selects `Re-run`                                                | Analyzer page opens with previously selected analyzers prefilled |
| 10 | User selects `Run analysis` again                                    | Analysis re-runs with same analyzers |
| 11 | User arrives at `Analyze code` page                                  | Analysis results are shown |
| 12 | User selects `Upload` again                                          | Redirected back to submission page |
| 13 | User selects `Delete` for uploaded file                              | Confirmation prompt appears |
| 14 | Confirmation prompt: "Delete this file? This cannot be undone."      | Prompt displayed with `Cancel` and `OK` options |
| 15 | User selects `Cancel`                                                | File remains, no changes made |
| 16 | User selects `OK`                                                    | File is deleted, success message: `Deleted 'sample-9be6ce3e361e.py' (944411681ce0…).` |
| 17 | User visits `/healthz` route                                         | JSON response: `{"status": "ok", "app": "my-python-buddy", "env": "dev", "version": "2025.09.08", "build": "local", "debug": true, "time": 1758069517.6039574}` |

**Post-Conditions:**  
- Application remains available and stable after restart (i.e. a CTRL + C and Uvicorn cmd line run).  
```bash
 uvicorn core.asgi:application --host 127.0.0.1 --port 8443 --ssl-certfile localhost+2.pem --ssl-keyfile localhost+2-key.pe
```
- Health API endpoint confirms environment variable override.
