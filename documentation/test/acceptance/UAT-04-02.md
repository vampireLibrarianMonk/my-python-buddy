# User Acceptance Test 04-02 Run and Submitted File Deletion

**Test Type:** User Acceptance
**Context:** Database Models and Administration
**Context Ladder:** Local then Cloud Deployment
**Test ID:** UAT-04-02

**Description:**
This `User Acceptance` test validates that a `Run` and its associated `SubmittedFile` can be deleted in the correct dependency order through the Django Administration dashboard. The test ensures that when a `Run` is deleted, all dependent `Finding(s)` are removed automatically due to the cascade behavior defined in `models.py`. It also confirms that the `SubmittedFile` entry can subsequently be deleted once no related `Run` entries exist. Successful completion of this test demonstrates proper referential integrity and cascade deletion logic across related database objects.

The following models are for consideration:

- Finding
- Run
- SubmittedFile

**Preconditions:**

- Computer instance (private or cloud) with a reachable IP is provisioned with the server running the application.
- `User` has been notified that they have to accept self-signed certificate for HTTPS access.
- Database migrations have been applied successfully using `python manage.py migrate`.
- `User` has been given starter `SuperUser` credentials.
- `User` has uploaded a valid file from `sample_files` below and run at least one `analyzer`.
  - `bandit_ringer_test.py`
  - `pickle.py`

## Test Execution Steps

| Step | Action                                                                     | Expected Response                                                                      |
| ---- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 1    | `User` logs into the Django Administration panel.                          | Admin dashboard loads successfully.                                                    |
| 2    | Navigate to the **Run** section.                                           | Existing `Run` entries are listed.                                                     |
| 3    | Select a `Run` associated with a specific `SubmittedFile`.                 | Details for the selected `Run` (including `Finding(s)`) are displayed.                 |
| 4    | `User` attempts to find the deletion checkbox to delete a specific finding | `User` is unable to delete `Finding(s)`.                                               |
| 5    | Click **Delete** on the `Run` detail page and confirm deletion.            | The selected `Run` is deleted, and all related `Finding(s)` are automatically removed. |
| 6    | Navigate to the **SubmittedFile** section.                                 | The associated `SubmittedFile` remains listed but now shows no related `Run(s)`.       |
| 7    | Select the same `SubmittedFile` entry and click **Delete**.                | The `SubmittedFile` entry is deleted successfully from the database.                   |
| 8    | Refresh the Admin dashboard view.                                          | Neither the `Run` nor its associated `SubmittedFile` appear in the listings.           |

**Post-Condition:**

- Both the selected `Run` and `SubmittedFile` are fully deleted from the database.
- All `Finding(s)` that were associated with the deleted `Run` are automatically removed via cascade behavior.
